Overview

DynamicMap is the play-time plugin for maps exported from the Dynamic Map Builder. It loads the builder's gameplay bundle and shows it on the table screen with the same session tools used by the standard Map plugin.

DynamicMap can show:

  • The bundled background texture and its builder calibration.
  • Exported wall geometry for player-character sightlines, static point lights, and sunlight areas.
  • Grid overlay, fog of war, tracker tokens, token names, and measurement overlays.

Loading Dynamic Maps

Add or switch a DM pane to DynamicMap, then click Load Dynamic Map.... Choose a .dynamicmap gameplay bundle, or a zip file produced by the Dynamic Map Builder export workflow.

DynamicMap reads the bundle directly. The background image is loaded from inside the bundle when one is present, so the original source texture file does not need to stay beside the map.

Click Clear Dynamic Map to remove the loaded bundle from the table view while keeping other session controls available.

Table View

If both the standard Map plugin and DynamicMap are loaded, the main toolbar shows a Table content selector. Choose DynamicMap when you want the player-facing table screen to show a dynamic map bundle. Choose Map to return to the standard image-map view.

The screen selector still controls which physical display receives the borderless table window. The table-content selector only chooses which plugin supplies that window's map.

Runtime Features

DynamicMap copies the standard map play controls so a dynamic bundle can be run like a normal encounter map.

FeatureWhat it does in DynamicMap
MinimapShows the loaded dynamic map, fog state, and token positions for the DM.
RenderModeUses the normal play view. Exported walls, light handles, and sunlight outlines are hidden. Walls still block player-character sightlines and point-light bright cores, while dim light reaches softly through nearby spaces.
DebugModeShows exported walls in the same solid accent colour used by the builder, draws point-light halos with separate bright and dim radius areas, and shows sunlight areas as translucent polygons for setup checks.
GridCan be shown or hidden and recoloured. Loading a bundle centers the grid on the exported map bounds.
Fog of warPaint or erase fog on the minimap. By default, a loaded bundle uses fog coverage matching its exported map size.
TokensTracker combatants appear as draggable tokens with colour, size, image, and name support. Actors marked as PCs reveal only lit areas they can see through exported walls when the loaded bundle contains authored lighting. PC darkvision reveals nearby wall-blocked terrain in black and white. Bundles without lights, sunlight areas, or PC darkvision keep sight-only visibility.
MeasurementsLine, cone, rectangle, and circle overlays can be DM-only or mirrored to the table screen.
Table movementThe whole rendered table map can be nudged or re-centered without editing the exported bundle.

Dynamic maps keep their builder orientation and background calibration. The standard image-map rotation and image calibration controls are not shown because the background, walls, and lights must remain aligned with the exported grid.

The sightline layer uses the same look as fog of war. Areas that PCs have never seen are fully black on the player-facing table screen; areas seen before but no longer visible stay softly greyed. When the bundle contains authored lighting, current visibility is limited to places that are both seen by a PC and lit by a point light or sunlight area, plus any area revealed by a PC's darkvision. Point lights also tint the currently visible map with the colour chosen in the builder. Terrain seen only through darkvision is shown in black and white. The DM minimap remains visible to the DM. Moving an NPC token does not recalculate sightlines. When several PCs are active, moving one PC recalculates that PC's sightline in the background and reuses the other PCs' cached sightlines.

NPC tokens appear on the table as soon as any part of their token circle enters a PC sightline, even if the token centre is still behind a wall. Previously seen grey areas do not reveal NPCs or show their movement.

Builder Data

Runtime bundles include only play-time data: map size, optional background texture, background calibration, walls, lights, and sunlight areas. Builder-only details such as construction-site names, wall labels, light labels, sunlight-area labels, outline groups, and editor layer visibility are not shown during play.

In RenderMode, exported walls, light handles, and sunlight outlines are not drawn directly. In DebugMode, walls are drawn as solid accent-colour guide lines, enabled point lights appear as two-radius coloured halos, and sunlight areas appear as translucent polygons. Disabled lights remain visible to the DM as subdued markers in DebugMode, but player-facing light markers are hidden.

Wall geometry controls player-character sightlines during play and also blocks each point light's bright core. Enabled point lights illuminate softly out to their dim radius even around wall corners, tint visible areas with their builder colour, sunlight areas are always lit, and PC darkvision reveals wall-blocked grayscale terrain from that PC's token. If a bundle has no lights, sunlight areas, or PC darkvision, DynamicMap keeps the older sight-only behavior.

Scenes

DynamicMap participates in the shared Scenes... browser. A saved scene records the loaded bundle path, table offset, grid settings, fog of war, token positions, and measurement state. Loading the scene restores that DynamicMap setup alongside the other scene-aware plugins.
