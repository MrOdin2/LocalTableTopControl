Overview

DynamicMap is the play-time plugin for maps exported from the Dynamic Map Builder. It loads the builder's gameplay bundle and shows it on the table screen with the same session tools used by the standard Map plugin.

DynamicMap can show:

  • The bundled background texture and its builder calibration.
  • Exported soft walls, hard walls, doors, feature walls, static point lights, and sunlight areas for player-character sightlines and lighting.
  • Grid overlay, fog of war, tracker tokens, token names, and measurement overlays.

Loading Dynamic Maps

Add or switch a DM pane to DynamicMap, then click Load Dynamic Map.... Choose a .dynamicmap gameplay bundle, or a zip file produced by the Dynamic Map Builder export workflow.

DynamicMap reads the bundle directly. The background image is loaded from inside the bundle when one is present, so the original source texture file does not need to stay beside the map.

Click Clear Dynamic Map to remove the loaded bundle from the table view while keeping other session controls available.

Table View

If both the standard Map plugin and DynamicMap are loaded, the main toolbar shows a Table content selector. Choose DynamicMap when you want the player-facing table screen to show a dynamic map bundle. Choose Map to return to the standard image-map view.

The screen selector still controls which physical display receives the borderless table window. The table-content selector only chooses which plugin supplies that window's map.

Runtime Features

DynamicMap copies the standard map play controls so a dynamic bundle can be run like a normal encounter map.

FeatureWhat it does in DynamicMap
MinimapShows the loaded dynamic map, fog state, token positions, and every door icon for the DM.
RenderModeUses the normal play view. Exported walls, light handles, and sunlight outlines are hidden. Visible doors show a door icon on the player-facing table view. Closed walls, doors, and blocking feature-wall sides affect player-character sightlines and point-light bright cores. Dim light reaches softly through soft walls and Soft feature-wall sides, but hard walls, closed doors, and Hard feature-wall sides block dim light.
DebugModeShows exported walls with the same soft/hard/door/feature styling used by the builder. Feature walls show front and back as separated side lines: Open is dotted, Soft is dashed, and Hard is solid. DebugMode also draws point-light halos with separate bright and dim radius areas, and shows sunlight areas as translucent polygons for setup checks.
GridCan be shown or hidden and recoloured. Loading a bundle centers the grid on the exported map bounds.
Fog of warPaint or erase fog on the minimap. By default, a loaded bundle uses fog coverage matching its exported map size.
TokensTracker combatants appear as draggable tokens with colour, size, image, and name support. Actors marked as PCs reveal only lit areas they can see through exported walls when the loaded bundle contains authored lighting or a PC has a light source. PC light sources move with the token. PC darkvision reveals nearby wall-blocked terrain in black and white. Bundles without lights, sunlight areas, PC light sources, or PC darkvision keep sight-only visibility. Force PCs keeps PC tokens visible on the table even when fog or darkness would normally hide them.
MeasurementsLine, cone, rectangle, and circle overlays can be DM-only or mirrored to the table screen.
Table movementThe whole rendered table map can be nudged or re-centered without editing the exported bundle.

Dynamic maps keep their builder orientation and background calibration. The standard image-map rotation and image calibration controls are not shown because the background, walls, and lights must remain aligned with the exported grid.

When a combatant is the current initiative actor and has movement remaining, DynamicMap highlights the grid cells that token can reach. PC highlights can appear on the table view and follow the live token position as web movement is spent. NPC highlights are shown only on the DM minimap and stay anchored to the position where the turn or Dash was started, so quick DM drag/drop movement does not constantly redraw the reachable area. The highlight respects the dynamic map's walls and treats closed doors as blockers while open doors allow movement through. With the DynamicMap minimap focused, press Shift once to add an NPC Dash to the active NPC's movement; if you press Shift while dragging a token, the Dash is applied when you drop it.

Left-click a door icon on the DM minimap to open or close that door. The icon stays in place as the click target, but an open door stops blocking sightlines and light. Hidden doors can only be seen and toggled from the DM minimap; the player-facing table view only shows icons for doors marked visible in the builder.

The sightline layer uses the same look as fog of war. Areas that PCs have never seen are fully black on the player-facing table screen; areas seen before but no longer visible are shown in black and white with a soft grey cover. When the bundle contains authored lighting, current visibility is limited to places that are both seen by a PC and lit by a point light, sunlight area, or PC-carried light source, plus any area revealed by a PC's darkvision. Soft walls and Soft feature-wall sides let dim light spread around corners, while hard walls, closed doors, and Hard feature-wall sides stop dim light. Open feature-wall sides let sight and light pass from that side, while the opposite side can still block them. Point lights also tint the currently visible map with the colour chosen in the builder. Terrain seen only through darkvision is shown in black and white. The DM minimap remains visible to the DM. Moving an NPC token does not recalculate sightlines. Turn on Force PCs when you want player-character tokens to stay visible to the players even if the token is standing in fog, darkness, or an unseen area. NPC visibility is not changed by this option. When several PCs are active, moving one PC recalculates that PC's sightline in the background and reuses the other PCs' cached sightlines.

NPC tokens appear on the table as soon as any part of their token circle enters a PC sightline, even if the token centre is still behind a wall. Previously seen grey areas do not reveal NPCs or show their movement.

Builder Data

Runtime bundles include only play-time data: map size, optional background texture, background calibration, soft walls, hard walls, doors, feature walls, lights, and sunlight areas. Builder-only details such as construction-site names, wall labels, light labels, sunlight-area labels, outline groups, and editor layer visibility are not shown during play.

In RenderMode, exported walls, light handles, and sunlight outlines are not drawn directly. In DebugMode, soft walls are drawn as lighter dashed guide lines, hard walls are drawn as stronger solid guide lines, doors include door icons, feature walls show separated front/back side lines plus normal arrows, enabled point lights appear as two-radius coloured halos, and sunlight areas appear as translucent polygons. Disabled lights remain visible to the DM as subdued markers in DebugMode, but player-facing light markers are hidden.

Wall geometry controls player-character sightlines during play and also blocks each point light's bright core. Feature walls apply their Open, Soft, or Hard behavior from the side the viewer or light is on. Enabled point lights illuminate softly out to their dim radius through soft walls and Soft feature-wall sides, hard walls, closed doors, and Hard feature-wall sides block dim light, tint visible areas with their chosen colour, sunlight areas are always lit, PC light sources follow their token, and PC darkvision reveals wall-blocked grayscale terrain from that PC's token. If a bundle has no lights, sunlight areas, PC light sources, or PC darkvision, DynamicMap keeps the older sight-only behavior.

Scenes

DynamicMap participates in the shared Scenes... browser. A saved scene records the loaded bundle path, table offset, grid settings, fog of war, token positions, and measurement state. It also remembers which dynamic doors are open and whether PC tokens are forced visible. Loading the scene restores that DynamicMap setup alongside the other scene-aware plugins.
