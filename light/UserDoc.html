Overview

The Ambient Lighting plugin lets you control WLED-compatible RGB LED strips from TabletopControl. Wrap LED strips around your table, behind your screen, or around your dice tower to create immersive, scene-appropriate lighting that changes as the adventure unfolds.

The plugin communicates with a WLED device over a serial (USB) connection. No Wi-Fi or network configuration is required — just a USB cable between the DM's computer and the microcontroller running WLED.

What is WLED? WLED is free, open-source firmware for LED controllers (such as ESP8266 and ESP32). It runs on inexpensive hardware and gives you a huge range of lighting effects. See kno.wled.ge for more information.

Hardware Setup

To use the Ambient Lighting plugin you need:

  1. A microcontroller (e.g. ESP8266 or ESP32) flashed with WLED firmware.
  2. An addressable RGB LED strip (WS2812B or similar) wired to the controller.
  3. A USB cable connecting the controller to the computer running TabletopControl.

Once the hardware is connected and powered, the controller should appear as a serial device (e.g. /dev/ttyUSB0 on Linux).

Note: You may need to install a USB-to-serial driver for your microcontroller. On Linux, most controllers are recognised automatically. On other systems, check the controller manufacturer's documentation.

Connecting to the Device

In the Ambient Lighting panel on the DM screen:

  1. Select the Serial Port from the dropdown. The list shows all available serial ports detected by the system. If your device is not listed, check that it is plugged in and powered, then click the refresh button next to the dropdown.
  2. Select the Baud Rate. For most WLED-based controllers the default is 115200. Check your WLED device configuration if unsure.
  3. Click Connect. The status label changes to Connected if successful, or shows an error message if the connection failed. If TabletopControl cannot open the selected port, it also opens an error dialog with the reason so you do not need to guess what went wrong.

To disconnect, click Disconnect. All lighting controls remain visible so you can reconnect without losing your settings.

If the light state cannot be sent after you are connected (for example because the cable was unplugged or the controller stopped responding), the connection status switches to an error message and the same shared error dialog is shown once so you can react without being flooded by repeated popups.

Tip: TabletopControl does not remember the serial port between sessions. Make a note of the port name (e.g. /dev/ttyUSB0) so you can select it quickly next time.

Power Control

The Power toggle turns the LED strip on or off without disconnecting from the serial port. Use this to quickly black out the lights without changing any settings.

When power is off, all other controls (colour, effects, brightness) retain their last values. Turning power back on restores the lights to the previous state.

Colour

In the colour row, click the swatch/hex control to open the colour editor dialog. The dialog includes a colour wheel for hue/saturation selection plus direct input fields for Hex, RGB, and HSV values (matching the controls from JavaFX’s custom-colour editor). The same shared editor is used in other plugins (for example the Audio Soundboard) so colour picking behaves consistently.

Changes in the dialog are staged. Use OK to apply the new colour to the LED strip, or Cancel to discard edits and keep the current colour.

A live preview updates as you edit values so you can confirm the selected colour before applying it.

The chosen colour is used as the base colour for all static effects (such as None and Fade). Dynamic colour effects such as Rainbow ignore the selected colour and generate their own palette.

Effects

Select a lighting effect from the Effect dropdown to animate the LED strip. The effect starts immediately. Effects marked with ✱ use the selected colour as their base; others generate their own palette automatically.

Effect Speed & Intensity

Below the Effect selector you will find two sliders: Speed and Intensity. Both range from 0% to 100% in the interface, and map in the background to the WLED segment parameters sx (speed) and ix (intensity) from 0 to 255.

Brightness

The Brightness slider sets the overall brightness of the LED strip from 0% (off) to 100% (maximum). Adjusting brightness is separate from the power toggle — setting brightness to 0% dims the lights but does not send a power-off command.

For a subtle ambient glow during normal play, 20–40% brightness is often ideal. Increase for dramatic reveals or energetic scenes.

Colour Cycling

Enable the Colour Cycling checkbox to make the LED strip automatically cycle through all hues over time, starting from the currently selected colour. This is different from the Rainbow effect — cycling rotates the chosen base colour slowly, while Rainbow sweeps through the entire spectrum rapidly on the strip itself.

Use colour cycling when you want a slow, atmospheric mood shift rather than a visually busy animation.

Presets

WLED devices support numbered presets (1–250) that are stored on the device itself. A preset can contain any combination of effect, colour, speed, and intensity settings that you have configured directly on the WLED device using its own web interface.

In the Lighting panel, type a preset number into the Preset field and press Enter (or click Apply Preset) to activate it. The device switches to that preset immediately.

If the value is not a whole number between 1 and 250, the preset status line tells you what to fix and keeps the previous preset active.

Tip: Set up your favourite lighting scenes as presets on the WLED device in advance. During a session you can switch between them with a single number entry — much faster than manually adjusting colour, effect, and brightness individually.

Debug Console

The Debug Console includes a toggle that turns command logging on or off. When logging is enabled, the console displays a live log of all serial commands sent to the WLED device. Each line shows the JSON payload that was transmitted.

This is primarily useful for troubleshooting — if the lights are not responding as expected, the console can confirm whether the correct command was sent. If a serial write fails, the console also adds a single error line for that failure period.

The console is not needed during normal use and logging can be left disabled.
