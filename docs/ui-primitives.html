Overview

The Core UI Primitives package (com.tabletopcontrol.core.ui) provides a consistent, plugin-agnostic foundation for two common UI patterns:

  • Context menus — a structured model of actions that are rendered into a JavaFX ContextMenu with canonical section ordering, automatic separators, greyed-out disabled items, and optional confirmation dialogs.
  • Drag-and-drop reordering — a centralised helper that attaches consistent drag-source and drop-target behaviour to any node in an item list, including ghost previews, visual drop indicators, and auto-scroll.

Plugins use these primitives instead of hand-rolling their own ContextMenu or setOnDragDetected wiring, which ensures visual and behavioural consistency across the entire application.

Package: com.tabletopcontrol.core.ui — all classes listed in this guide live in this package.

Context Menus

Context menus are built from a list of MenuAction objects and rendered by ContextMenuRenderer. Actions are grouped into standard sections and separated automatically.

MenuAction

MenuAction is a plain Kotlin data class describing a single menu item. It carries no JavaFX state, making it easy to construct, copy, and test in isolation.

PropertyTypeDefaultDescription
idString—Stable, unique identifier (e.g. "tracker.rename"). Used for contributor override/merge: contributor actions replace base actions with the same id in-place; last contributor wins for the same id.
labelString—Human-readable text shown in the menu item.
iconString?nullOptional Unicode glyph or emoji prepended to the label (e.g. "🗑️").
sectionMenuSectionBASICWhich standard section this action belongs to.
isEnabledBooleantrueWhen false, the item is shown greyed-out and cannot be triggered.
isVisibleBooleantrueWhen false, the item is excluded from the menu entirely.
requiresConfirmationBooleanfalseWhen true, a confirmation dialog is shown before invoking onAction.
confirmationMessageString?nullText shown in the confirmation dialog (falls back to a generic phrase when null).
onAction() -> Unit—Callback invoked when the user selects the item (after any confirmation).

MenuSection

Actions are grouped into one of four standard sections. Sections are always rendered in the order listed below, with SeparatorMenuItems between populated sections. Sections containing no visible actions are silently omitted.

SectionOrderTypical actions
BASIC1stOpen, rename, view details, refresh — the most-used everyday operations.
APPEARANCE2ndChange colour, icon, or label — visual customisation that doesn't alter structure.
ARRANGE3rdMove up/down, move to group, pin — structural or ordering changes.
DANGER_ZONE4th (last)Delete, reset, clear — destructive operations, always placed last and typically paired with requiresConfirmation = true.

ContextMenuRenderer

ContextMenuRenderer is a singleton object with a single public method: 

fun build(
    actions: List<MenuAction>,
    contributors: List<MenuContributor> = emptyList(),
    context: Any? = null,
): ContextMenu
  • actions — the base list of actions provided by the menu host.
  • contributors — optional list of MenuContributor instances; contributor actions with a matching id replace the corresponding base action in-place (preserving base ordering). When multiple contributors supply the same id, the last contributor's action wins.
  • context — forwarded verbatim to every contributor's contributeActions(context).

The returned ContextMenu is ready to be shown immediately. Attach it to a node with setOnContextMenuRequested: 

val menu = ContextMenuRenderer.build(
    actions = listOf(
        MenuAction(
            id      = "entry.view",
            label   = "View Details",
            icon    = "📄",
            onAction = { openDetails(item) },
        ),
    ),
)
node.setOnContextMenuRequested { e ->
    menu.show(node, e.screenX, e.screenY)
    e.consume()
}

MenuContributor

MenuContributor is an interface that any class (including a plugin) can implement to contribute additional actions to a shared context menu, or to override existing actions by matching their id. 

interface MenuContributor {
    fun contributeActions(context: Any?): List<MenuAction>
}

Override semantics: if a contributor returns an action with the same id as an action in the base list, the contributor's version replaces it in-place, preserving the original base ordering. When multiple contributors supply the same id, the last contributor's action wins (last-write semantics). New actions (ids not present in the base list) are appended after the base actions in last-write order.

Principle: contributors extend, not replace, the whole menu. They can add new actions to any section or override specific base actions — but they cannot remove an action that has no matching id. Use isVisible = false in an overridden action to effectively hide a base action.

Drag & Drop

The drag-and-drop primitives centralise all visual interactions for item reordering: ghost preview, drop indicator, and auto-scroll. Plugin code only provides a DragDropContext with the format identifier and a reorder callback.

Use com.tabletopcontrol.core.ui.reorder.ReorderSupport inside onReorder to centralise index validation and drop-target adjustment (including append drops at listSize).

DragDropContext

A plain data class that bundles the configuration for one drag-and-drop list. Create a single instance per list/container and reuse it for every item node.

PropertyTypeDefaultDescription
dataFormatString—Unique MIME-type-like key (e.g. "tabletopcontrol/tracker-item"). Ensures drops are accepted only from the same list type.
ghostFactory((Node) -> Node)?nullOptional factory for a custom ghost-preview node. When null, a snapshot of the drag source is used.
onReorder(Int, Int) -> Unit—Called with (fromIndex, toIndex) on a successful drop. Update your data model and refresh the UI here.
canAcceptDrop(String) -> Boolean{ true }Optional predicate to veto a drag-over event based on the raw source-data string.
autoScrollPaneScrollPane?nullIf set, the scroll position is adjusted automatically when the cursor approaches the pane's edges during a drag.

DragDropSupport

A singleton object with two installation methods:

installDragSource

fun installDragSource(
    node: Node,
    index: Int,
    context: DragDropContext,
)

Attaches setOnDragDetected to node. When the user starts a drag, the item's index is written to the dragboard. The ghost image is produced by DragDropContext.ghostFactory (or a transparent snapshot of node if no factory is set).

installDropTarget

fun installDropTarget(
    node: Node,
    index: Int,
    context: DragDropContext,
    dropIndicator: DropIndicator? = null,
)

Attaches drag-over, drag-exited, and drag-dropped handlers to node. On a valid hover, the optional dropIndicator is shown and auto-scroll is triggered. On drop, DragDropContext.onReorder is called.

DropIndicator

A thin (3 px) horizontal bar that signals a valid drop position. Create one instance for your list container and pass it to DragDropSupport.installDropTarget. It manages its own isVisible state automatically, while isManaged remains false so showing the indicator does not affect layout or cause flicker. If you later rebuild the container with children.setAll(...) (or any other operation that replaces the child list), include the indicator in the new children or re-add it afterwards, because replacing the child list removes it. 

val indicator = DropIndicator()
listContainer.children.add(indicator)   // initial setup

// later refreshes that replace children must preserve the indicator
listContainer.children.setAll(items + indicator)

The bar uses the application's -tc-accent CSS variable for its colour, so it automatically matches the user's selected theme. You may also style it via the tc-drop-indicator CSS class.

GrabHandle

A Label subclass displaying the braille-dots glyph ⠿ (U+28BF) as a visual drag handle. Add it to the left edge of any draggable row. 

val handle = GrabHandle()
val card   = HBox(handle, nameLabel, spacer, removeButton)

The handle applies an open-hand cursor and the tc-grab-handle CSS class. Its presence is purely cosmetic — the drag is initiated by DragDropSupport.installDragSource on the parent card node itself, so a drag gesture on the card (including the handle area) begins the drag.

Full Examples

Basic Context Menu

A right-click menu on a soundboard button with a DANGER_ZONE "Clear" action that requires confirmation: 

val actions = listOf(
    MenuAction(
        id      = "sound.load",
        label   = "Load Sound…",
        icon    = "📂",
        section = MenuSection.BASIC,
        onAction = { openFileChooser(slot) },
    ),
    MenuAction(
        id                   = "sound.clear",
        label                = "Clear",
        icon                 = "🗑️",
        section              = MenuSection.DANGER_ZONE,
        isEnabled            = slot.isLoaded,
        requiresConfirmation = true,
        confirmationMessage  = "Remove the loaded sound from this slot?",
        onAction             = { clearSlot(slot) },
    ),
)

button.setOnContextMenuRequested { e ->
    ContextMenuRenderer.build(actions).show(button, e.screenX, e.screenY)
    e.consume()
}

Extending a Menu via MenuContributor

A plugin adds an "Export to CSV" action to a tracker item's context menu without modifying the host plugin's action list: 

// In MyPlugin.kt
class MyPlugin : DmPlugin, MenuContributor {

    override val displayName = "My Plugin"
    override fun createView(): Node = buildUi()

    override fun contributeActions(context: Any?): List<MenuAction> {
        // context is whatever the menu host passes (e.g. a TrackerEntry)
        val entry = context as? TrackerEntry ?: return emptyList()
        return listOf(
            MenuAction(
                id      = "myplugin.export",
                label   = "Export to CSV",
                icon    = "📤",
                section = MenuSection.ARRANGE,
                onAction = { exportEntry(entry) },
            ),
        )
    }
}

// In the host plugin, when building the menu:
ContextMenuRenderer.build(
    actions      = baseActions,
    contributors = listOf(myPluginInstance),
    context      = clickedEntry,
)

Reorder Helper (index math)

ReorderSupport encapsulates the index math above drag/drop primitives: 

import com.tabletopcontrol.core.ui.reorder.ReorderSupport

val ctx = DragDropContext(
    dataFormat = "tabletopcontrol/example-row",
    onReorder = { from, dropTarget ->
        if (!ReorderSupport.reorderMutableListFromDrop(rows, from, dropTarget)) {
            return@DragDropContext
        }
        refresh()
    },
)

If you need to reorder multiple parallel lists, compute one shared plan and apply it to each list so they stay aligned: 

val plan = ReorderSupport.planDropReorder(entries.size, from, dropTarget) ?: return
tracker.move(plan.fromIndex, plan.toIndex)
ReorderSupport.reorderMutableList(tokenIds, plan)

Reorderable List with Grab Handles

A complete minimal example of a vertically reorderable list using all four drag-and-drop primitives together: 

class MyListView {

    private val items = mutableListOf("Alpha", "Beta", "Gamma")
    private val container = VBox(4.0)
    private val scrollPane = ScrollPane(container)
    private val indicator  = DropIndicator()

    // One DragDropContext shared across all item nodes in this list.
    private val dndCtx = DragDropContext(
        dataFormat      = "tabletopcontrol/my-list-item",
        autoScrollPane  = scrollPane,
        onReorder       = { from, to ->
            val moved = items.removeAt(from)
            items.add(to, moved)
            refresh()
        },
    )

    fun build(): Node {
        refresh()
        return scrollPane
    }

    private fun refresh() {
        container.children.setAll(
            items.mapIndexed { index, name -> makeCard(index, name) }
        )
        container.children.add(indicator)
    }

    private fun makeCard(index: Int, name: String): Node {
        val handle = GrabHandle()
        val label  = Label(name)
        HBox.setHgrow(label, Priority.ALWAYS)
        val card = HBox(6.0, handle, label)

        DragDropSupport.installDragSource(card, index, dndCtx)
        DragDropSupport.installDropTarget(card, index, dndCtx, indicator)

        return card
    }
}

Extension Points

The primitives are designed for extension through composition, not subclassing:

  • Contribute menu actions — implement MenuContributor and pass the instance to ContextMenuRenderer.build(contributors = ...). Plugins must never call ContextMenu directly when the host uses ContextMenuRenderer.
  • Override a base action — return a MenuAction with the same id from your contributor. The base action is replaced by yours before rendering.
  • Custom ghost preview — supply a ghostFactory in DragDropContext. The factory receives the dragged Node and should return a new node (e.g. a styled clone or a simplified thumbnail).
  • Conditional drop acceptance — supply canAcceptDrop in DragDropContext to veto drops based on the raw source-data string (e.g. accept only items from the same category).
Do not extend ContextMenuRenderer or DragDropSupport by subclassing — both are object singletons. All customisation goes through the data classes (MenuAction, DragDropContext) and the MenuContributor interface.
