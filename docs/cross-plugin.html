Overview

While each plugin works independently, the Initiative Tracker and Map and DynamicMap plugins share information automatically so you don't have to manage tokens on the map separately from the combat tracker.

The link between them is one-way: the Tracker publishes information (combatant added, moved, image changed, removed) and the active map runtime listens and updates the table screen accordingly. You control everything from the Tracker side.

Scene Browser

The Scenes... button in the main toolbar is the shared cross-plugin way to capture and restore a full encounter setup. A scene can include:

  • Map image, calibration, token positions, fog of war, and open DynamicMap doors.
  • Tracker actors with their live HP, AC, initiative, and token settings.
  • Music tracks and volume settings.
  • Soundboard button assignments and order.
  • Ambient light colour, effect, speed, intensity, and brightness.

Use Save Current Scene to capture the current setup. TabletopControl asks for a scene name and shows a confirmation dialog before saving. If that name already exists, it asks again before replacing the older scene.

Use Load beside any saved scene to restore it. Loading also shows a confirmation dialog because it replaces the current encounter state across all participating plugins.

Scene files are stored in the scene folder as readable plain-text XML, which makes troubleshooting much easier when you need to inspect a saved encounter by hand. Older scene files still load and are upgraded to the readable format automatically the next time TabletopControl reads them.

Scene loading also rebuilds preset-based token portraits if an older scene points to a temporary image file that no longer exists, and fog of war is stored in the shorter of the hidden-cell or revealed-cell lists to keep scene files compact.

Tip: Scenes are best for whole encounters or reusable battle maps. Presets are still the better choice for one reusable tracker actor or one reusable light preset stored on the WLED device.

Tracker ↔ Map Integration

Token Creation

When you add a combatant to the Initiative Tracker, a corresponding token is automatically created on the map. The token appears at a default position and can be moved to the correct location on the grid (see Positioning Tokens below).

Each token is uniquely tied to one combatant. If you add ten goblins, ten separate tokens appear — one per combatant card.

Colour Sync

The token's colour circle on the map always matches the combatant's colour swatch in the tracker. Changing the swatch colour in the tracker immediately updates the token colour on the map.

This lets you quickly distinguish between combatants at a glance — especially useful when there are several tokens of the same type on the map (e.g. multiple goblins). Assign each a distinct colour.

Size Sync

Token size is also shared between the tracker and the map. Right-click a combatant card in the tracker to choose Tiny (1/8 tile), Small (1/4 tile), Medium (1 tile), Large (2x2 tiles), Huge (3x3 tiles), or Gargantuan (4x4 tiles).

The map redraws the token immediately at the matching footprint, and older presets or saved data that do not include a size continue to use Medium.

If footprints overlap, smaller tokens are rendered above larger ones so tiny and small creatures stay readable on the table screen.

Token Images

When you upload a token image on a combatant's card in the tracker, that image is sent to the map and shown inside the token circle on the table screen.

You can also adjust the image scale and offset within the token circle from the tracker card. These adjustments are reflected on the map in real time.

Tip: Use circular portrait art (tokens) for the best appearance. Square or rectangular images work too — the circular clip just crops the edges.

Positioning Tokens on the Map

Token positions are managed through the minimap on the DM panel of the Map plugin. You can drag tokens on the minimap to move them to the correct grid cells. The table screen updates instantly.

Tokens snap to the map grid when a grid is enabled, so they stay aligned to grid squares automatically.

Multi-cell tokens can be grabbed from any covered cell on the minimap, and fog of war checks the whole footprint instead of only the token's top-left corner.

Tip: Use the Map plugin's minimap to move tokens during combat. The players see the updated position on the table screen as soon as you drop the token.

Removing Tokens

When you remove a combatant from the tracker (using the remove button on the combatant card, or via Clear All), the corresponding token is automatically removed from the map as well. No manual cleanup is needed.

Note: Using Clear All in the tracker removes every combatant and every token at once. A confirmation dialog is shown before this action proceeds.

Showing Token Names

The Map plugin has a Show Token Names toggle. When enabled, each token on the table screen displays a text label with the combatant's name drawn beneath the token circle. When disabled, tokens are shown as circles (or portrait images) only.

The name shown on the token always matches the name on the combatant's card in the tracker. Editing the name in the tracker updates the map label automatically.

DynamicMap Runtime

DynamicMap receives the same tracker token events as the standard Map plugin. Combatants, token colours, token sizes, token images, active-turn highlighting, and token removal stay synchronized through the shared event bus.

The tracker's PC marker also drives DynamicMap sightlines. Tokens belonging to PC actors reveal the areas they can see through the exported wall geometry. When the loaded dynamic bundle contains authored lights or sunlight areas, those PC sightlines are also limited to lit areas. A PC actor's light source in the tracker acts as a moving point light attached to that token, with separate bright and dim ranges and its chosen tint colour. DynamicMap uses the builder's soft, hard, and door wall kinds for lighting: all closed wall geometry blocks sightlines and bright light, while hard walls and closed doors also block dim light. Visible doors can show icons on the player-facing table view, and all doors show icons on the DM minimap so the DM can left-click a door to open or close it. A PC actor's darkvision range acts as a grayscale reveal from that token's position. If terrain is no longer currently visible and only remembered, DynamicMap keeps it grayscale so the table shows layout information without colour detail. The DynamicMap Force PCs option can keep PC tokens visible on the table even when fog or darkness would otherwise hide them; NPC tokens keep the normal visibility filtering. NPC movement does not recalculate that visibility layer.

When both Map and DynamicMap are available, use the toolbar's Table content selector to decide which one drives the player-facing table screen. The tracker can keep publishing token updates while you choose the map runtime that fits the current encounter.

DynamicMap also participates in shared scenes under its own scene key, so a scene can restore a dynamic bundle, fog state, token positions, and measurements independently from the standard Map plugin.

Dynamic Map Builder Pane Coordination

The Dynamic Map Builder workspace is made up of several cooperating panes plus workspace-level toolbar controls rather than one monolithic editor. The construction-site selector in the top toolbar chooses the active saved builder scene, and the same toolbar row exports gameplay-ready .dynamicmap bundles without builder-only names or groups. The main builder canvas, Wall Tools, Light Browser, and Outline Browser all share the same draft map and stay in sync automatically. Wall tools choose wall type separately from drawing mode, so soft walls, hard walls, and visible or hidden doors can be authored with the same shape tools; the exported wall kind and door visibility are consumed by DynamicMap during lighting and door handling.

This coordination is what lets you pick a light preset or start a sunlight-area polygon in one pane, place it on the canvas, then immediately manage that same light or area from the outline without switching workspaces.

Selecting an item in the outline highlights the same wall, light, or sunlight area in the main builder view, so the workspace behaves like one connected editor even though the tools live in separate panes.

Recommended Workflow for a Session

  1. Before the session: Load your map in the Map plugin and calibrate it. Set up fog of war — Hide All to cover the entire map.
  2. When an encounter begins: Add all combatants to the Initiative Tracker. Assign each a distinct colour and, optionally, a token image.
  3. Position tokens: Drag each token to its starting position on the minimap. Reveal the relevant fog of war area so the players can see the encounter space.
  4. During combat: Click Next Turn in the tracker to advance turns. Move tokens on the minimap as combatants move. Update HP and AC on the tracker cards as damage is dealt.
  5. After the encounter: Click Clear All in the tracker to remove all combatants and their tokens. Re-hide revealed fog of war if needed before the players explore further.
